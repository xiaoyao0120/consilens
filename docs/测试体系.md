# Consilens 测试体系

## 质量门禁

测试分为两层，避免把依赖 Docker 和大型数据库镜像的测试混入每次本地打包。

### 快速回归门禁（每次打包必跑）

```bash
./mvnw -B package
```

该命令必须覆盖并阻断以下回归：

- `examples` 下全部 YAML/JSON 配置可解析、校验并编译为 `CompareRequest`；
- 配置字段、枚举、场景目录和基线文件保持完整；
- `same-db` 示例、`ConnectorProvider`、`DatabaseDialectProvider` 三份 Connector 清单完全一致；
- 全部 Connector 的方言组件可装配，count/select、metadata、类型转换和时间归一化入口可生成非空 SQL；
- 各 Connector 模块的精确 SQL、Metadata、Dialect、DataType 单元测试；
- core 的 checksum、join、local diff、segment、planner、runtime 等确定性对比测试；
- CLI、sink、SPI、server、AI 等模块单元测试和最终打包插件。

GitHub CI 使用相同的 `package` 命令，防止出现“测试通过但产物打不出来”。禁止在日常质量门禁中使用 `-DskipTests`。

### Docker 真实数据库门禁（CI 与发布前）

```bash
scripts/release/release-check.sh --docker-verify-only
```

该脚本模式先要求 Docker daemon 可访问，再执行 `./mvnw -B -pl consilens-core -am verify`。`consilens-core` 的 `*ITest` 由 Failsafe 在 `integration-test/verify` 阶段执行，普通 `package` 不会执行。该层用于验证生成 SQL 能被真实数据库解析和执行，以及跨数据库差异结果。

脚本会删除旧的 Failsafe 报告，并要求本次执行生成至少一份 `TEST-*.xml` 报告、实际执行至少一个测试且 `skipped=0`。Docker 不可用、报告缺失、测试全空或任意跳过都会失败。因此 `@Testcontainers(disabledWithoutDocker = true)` 不能在 CI 或发布流程中被误报为通过。

`CrossDatabaseDockerITest` 和历史遗留的 `OceanBaseSameDbComparisonTest`、`OceanBaseCrossDbComparisonTest` 都依赖固定端口、账号和预置数据；默认 `verify` 明确排除它们，不会访问外部服务。只有在受控环境中才执行：

```bash
./mvnw -B -Pexternal-databases -pl consilens-core -am verify
```

GitHub CI 的 `CI-Docker-Verify` job 和 `scripts/release/release-check.sh` 均调用相同脚本。外部数据库 profile 不属于常规 CI/release 门禁，必须由拥有上述固定环境的受控流水线显式触发。

## 新增 Connector 的完成条件

新增 Connector 时必须同时完成：

1. 在插件聚合模块与 `consilens-connector-all` 中注册依赖；
2. 注册 `ConnectorProvider` 和 `DatabaseDialectProvider` SPI；
3. 增加 `examples/same-db/<type>` 与必要的 cross-db 场景；
4. 增加 SQL、Metadata、Dialect、DataType 四类方言测试；
5. 增加真实数据库 fixture 和新 Connector 链路集成测试。

任何一项缺失，都不应视为 Connector 测试体系完成。
