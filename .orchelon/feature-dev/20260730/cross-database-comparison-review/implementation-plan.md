# 实现计划

## 总体方案

保留 round-1 Review 的两个稳定单元，进入 round-2 修复。两个实现者按无重叠文件所有权并行修改；原 round-1 Reviewer 分别进行独立风险复审；主 Agent只做最终验收和跨单元集成验证。

## 分层修改

### 数据库和 SQL

- Schema 修改：无正式 Migration；新增多数据库示例建表与装载 SQL。
- Migration 策略：不适用。
- 数据回填：不适用。
- 回滚或前向修复：不适用。

### 后端

- API：无 HTTP API 变化。
- Service 或领域逻辑：SQL 差异列拼接、方言适配与表分段逻辑。
- Repository 或持久层：无。
- 校验和错误处理：重点检查空参数、负数/零分段、数值规范化。
- 权限或安全：重点检查示例中的默认凭据和命令调用边界。

### 前端

- 不适用。

### 测试

- 单元测试：OceanBase 比较测试改动与受影响模块测试。
- 集成测试：新增跨数据库集成测试的发现条件、退出语义与配置引用。
- 契约测试：YAML 字段与配置模型、连接器类型、SQL 表字段契约。
- UI 测试：不适用。
- Migration 验证：不适用。

## 仓库指令

- 对话提供的 `AGENTS.md`：JDK 11（以实际 `pom.xml` 为准）、四空格缩进、先读后写、精准改动、失败显式、修改后运行 Maven 验证；凭据必须外置，不得 stage、commit、push。
- 仓库内未发现额外 `AGENTS.md` 或 `agents.md`。

## 风险

- 跨 SQL 方言字符串拼接和数值格式化可能改变结果语义。
- 表分段计算涉及整数边界、空表和大数据量。
- 大量重复示例可能存在单个数据库字段、端口或命令错误。
- 集成测试可能因命名、注解或构建插件配置而未被默认执行。
- 暂存重命名可能留下旧路径引用。

## 非目标

- 不扩展新的比较功能或数据库类型。
- 不审查历史提交中的无关实现。
- 不逐行审查重复数据 fixture；对其做契约抽样和自动一致性检查。

## 完成定义

1. 两个实现单元满足 round-2 repair-request 和验收标准。
2. 两个实现单元均获得原独立 Reviewer 的有效 `pass`。
3. 主 Agent 对两个单元给出 `accept`。
4. 完成跨单元路径、配置、构建与测试检查，且 Review 后无未评审实质变更。
5. 最终报告准确反映实现、验证、风险和未完成范围。
